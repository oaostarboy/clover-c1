Presence · implementation snapshot

Continuity, without a second agent loop

A little more continuity.
No extra authority.

Optional presence can adapt the tone of a reply, carry an expressed open question, and offer a relevant connection later. It keeps model access, evidence, and user controls inside the existing boundaries.

Off by default.

This describes the implementation at the source revision below, not a release or deployment certificate. Presence must be explicitly enabled, and proactive settings, managed policy, scope, timing and budgets must also allow it. Opening this page changes nothing.

01 · Model handoff

The connection stays chosen.

An optional follow-up can happen after your requested reply has been delivered. The handoff preserves that reply's already-selected model connection for the callback, rather than letting a later task choose another account.

Requested replyThe normal worker has its selected connection.
→
Delivery confirmedThe surface acknowledges the requested reply.
→
Optional follow-upRecheck the same owner and all current gates.

If the selected owner disappears, changes, expires or loses access, optional work is withheld. It does not borrow a sibling account, refresh credentials, retry inference, or fall back to another provider or model.

Inherit is not auto-discovery

auxiliary.presence can explicitly configure a separate supported route. Otherwise the configured main route is inherited; auto means inherit, not search for a provider. The callback's selected-owner check still applies. Unsupported or unverified transport and budget combinations hold instead of silently switching paths.

The callback uses a short-lived, task-local owner handoff. It does not keep a copied credential context alive or grant new access.

02 · Emotion behavior

A response style, not a feeling.

A bounded assessment can consider the current human message in any language. It is no longer gated by a frustration keyword. Its output is a tentative interaction posture, not a claim that Clover feels an emotion or knows how you feel.

Implemented postures and their instructions
PostureWhat it asks the reply to do
ordinaryKeep the ordinary response style.
careful_briefBe careful and concise; acknowledge uncertainty.
gentleUse a gentle, matter-of-fact tone without diagnosis or assumed distress.
upbeatAcknowledge positive energy without forced cheer or exaggeration.
reflectiveAllow mixed reactions rather than flattening them into one emotion.
clarifyAcknowledge uncertainty; ask only a useful, brief clarification.

The assessment prompt covers calm, sadness, frustration, excitement, uncertainty and mixed reactions. It tells the model to abstain or lower confidence for ambiguity, sarcasm, negation, quotations and other people's feelings. These are instructions and safeguards—not a measured accuracy guarantee.

Short-lived and local to the turn

A reading lasts at most 120 seconds from observation. Confidence below 0.7 yields ordinary posture. Missing, invalid, stale or failed assessments do not invent a neutral reading.

No rewritten conversation

Style guidance is added only to the unsent current-user sidecar. It does not rewrite the cached system prefix, earlier messages, tools or permissions. New input, Stop, correction and revoked access fence stale work.

Only the latest reading is held in memory; it disappears on restart. No emotional history, personality profile, diagnosis or attachment score is added. Normal conversation storage remains separate.

03 · Automatic thoughts

Carry an open question.
Wait for a real connection.

The same optional assessment can capture one explicit, unresolved question or interest from your current authenticated message. You do not have to type Carry thought:, although that explicit path remains available.

Automatic capture is deliberately narrow: confidence must be at least 0.7; the model must classify the source as direct, current-human and unresolved; and the stored summary and quote must equal the entire exact current source, at most 512 UTF-8 bytes. Structural quotation, code delimiters and blockquotes independently block capture.

Illustration only · not a recorded model result

Earlier, you say
“I wonder how deployment packaging could be safer.”
Later, you add
“Deployment packaging now has a manifest checksum before publishing.”

That later message supplies new, related evidence. It can qualify for a connection decision; it does not guarantee a useful suggestion or a send.

Not a hidden task queue

The contract excludes commands, work obligations, resolved issues and third-party questions. A captured thought grants no permission to act, browse or research. There is no history scan, timer or new sensor.

Later means later

A new automatic capture cannot speak in its own turn. An existing relevant thought takes priority over a fresh current-turn assessment. A later successful reply must be acknowledged before an optional after-reply connection can be assessed and published.

Unchanged topics hold. Automatic thoughts require a connection decision citing the exact later current source and at least two of its new lexical anchors. This word-based gate can miss paraphrases or cross-language connections; it is not proof of understanding. A separately enabled desktop project-return opportunity exists, but a project view alone is not new conversation evidence.

On Telegram, the optional connection uses a separate plain message attempt. On desktop, it uses the status feed without taking focus or navigating. Ambiguous or missing delivery acknowledgements do not trigger automatic replay.

What persists

Pending thoughts and invalidation metadata are durable, scoped records; the default thought lifetime is one hour. Original evidence is checked again before use. Forget/correct clears the derivative and invalidates pending work, not the original chat message or every SQLite page and backup. Full storage stops new admission rather than silently recycling old records.

Unlinked conversations do not share thoughts. Cross-surface initiative sharing requires an explicit authenticated link in the same profile and exact project. That link does not share private emotion status or migrate old history.

04 · /emotions

Inspect without another model call.

/emotions

This human command reads status. It does not run inference, enable presence, reset a budget, resume work, look up credentials, or change a setting. It takes no arguments; there is no /emotions on, off or set mode.

  • Interaction posture: the actual current response style, explicitly labelled as style rather than felt emotion.
  • Tentative user affect: valid recent valence, arousal and confidence, with age and time to expiry—or unknown. Source text is withheld.
  • Feature and initiative state: enabled/disabled, holds, Stop and effective assessment limits.
  • Configured route and budget mode: provider/model metadata, not proof that credentials, dispatch admission or a server cap are valid.

Private Telegram and the authenticated owning desktop session can disclose their own valid reading. Other shared or unsupported messaging surfaces receive a private-conversation instruction, not private affect data. The CLI has no authenticated affect-owner binding, so it reports unknown affect while still showing available profile control and quota metadata.

Unknown is intentional. A missing, expired, revoked or inaccessible reading must not become a made-up “neutral” emotion. The command does not create a conversational evidence event or cancel an ongoing reply.

05 · Your controls

You can inspect, correct and stop.

Presence controls use the existing authenticated surface ownership and managed-policy gates. These command forms are available in the supported private Telegram and authenticated desktop paths.

ControlEffect
/proactive presence statusInspect exact-context thought records and presence control state.
/proactive presence stopStop optional presence across the profile. Requested replies remain available.
/proactive presence forget <id>
/proactive presence correct <id>		Clear the exact thought's derivative, invalidate its source revision and stop presence. Use Carry thought: to supply a replacement.
/proactive presence resumeReset for future thoughts only. Does not enable disabled settings, refund quota or replay unknown sends.
Presence: ordinaryClear tentative posture on the next requested turn; this is not a disable command.

Desktop initiative cards also expose Inspect, Forget, Correct and Stop. Generic Telegram /stop and authenticated desktop interruption also revoke the profile's pending presence work.

To disable the optional feature, the existing configuration command is clover config set presence.enabled false. Normal OFF writes revoke pending work before saving. Turning it on again resets old pending records rather than replaying them; ordinary requested replies remain separate.

06 · Limits & sources

Bounded calls.
Bounded claims.

Current-turn assessment and later connection decisions share a durable profile-wide allowance: at most one attempt per event and three per day, or a lower configured limit. Errors, rejection and timeouts consume reservations. There are no inference retries, automatic fallback or uncounted extra assessment calls.

The output envelope is at most 512 requested tokens, further limited by policy. strict_tokens is the default budget mode and admits only implemented, recognized all-generated-output limit contracts. Unsupported strict routes hold. Explicit requests mode changes the contract; it is not a hard token or cost guarantee.

Inference transport has a maximum five-second deadline and a retained-response byte limit. Closing a local connection does not prove remote generation or billing stopped. Missing usage is unknown, not zero.

What the evidence does—and does not—show

Source-pinned offline tests exercise integration, identity, quota, status and delivery boundaries with scripted model responses. They do not establish real-model emotion accuracy, confidence calibration, useful thought extraction, or universally correct speaker attribution. Incorrectly labelled indirect speech without quotation delimiters can still pass conservative capture checks.

This page makes no claim that a full repository suite, native Windows/macOS checks, install/update/rollback tests or live-model smoke tests have passed. Publication and activation are separate operations.
